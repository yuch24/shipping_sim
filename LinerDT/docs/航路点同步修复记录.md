# 航线同步修复记录

## 问题现象

前端地图上彩色航线（蓝/绿/橙）正确绕行好望角、沿海岸线，但船舶实际运行轨迹走的是白色直线（穿陆地、不走好望角），两者不一致。

## 根因分析

| 层级 | 数据源 | 问题 |
|---|---|---|
| **前端航线绘制** | `route_waypoints.csv` | ✅ 手工调校的26条航段，好望角绕行+沿岸+回程 |
| **前端航迹线颜色** | `getTrailColor()` 默认白色 | ❌ 无CII评级时返回白色alpha=0.3，和彩色航线冲突 |
| **后端船舶位置** | `VisualizationSync._find_safe_waypoints()` | ❌ 动态算法简单（只加一个偏移点），完全不走CSV路径 |
| **后端港口坐标** | `aeu_data.py AEU_PORT_COORDS` | ❌ CNSHA旧坐标(30.6306,122.0733)，前端已改为(30.5821,121.0734) |

**核心矛盾**：前端用CSV精心调校的航路点画航线，后端用简单算法算船位置，两边数据源完全不同。

## 修复策略：统一航路点数据源

**原则**：让后端船舶位置插值也使用 `route_waypoints.csv` 的航路点，使船轨迹和前端航线100%一致。

### 修改清单

### 1. 创建后端航路点加载器

**新文件**: `backend/app/data/waypoints_loader.py`

```python
# 从 route_waypoints.csv 加载航路点
# key格式: "from_port→to_port"（如 "CNTAO→CNSHA"）
# 反向航段自动翻转航路点顺序
WAYPOINT_SEGMENTS: dict[str, list[tuple[float, float]]] = _load_route_waypoints()

def get_waypoints(from_port: str, to_port: str) -> list[tuple[float, float]]:
    key = f"{from_port}→{to_port}"
    if key in WAYPOINT_SEGMENTS:
        return WAYPOINT_SEGMENTS[key]
    reverse_key = f"{to_port}→{from_port}"
    if reverse_key in WAYPOINT_SEGMENTS:
        return list(reversed(WAYPOINT_SEGMENTS[reverse_key]))
    return []  # 无CSV航段时回退到动态算法
```

**数据文件**: `backend/app/data/route_waypoints.csv`（从前端复制）

### 2. 修改 VisualizationSync 接受外部航路点

**文件**: `backend/app/scheduler/visualization_sync.py`

- `SailingSegment.waypoints` 默认值从 `None` 改为 `field(default_factory=list)`
- `register_sailing()` 新增参数 `waypoints: list[tuple[float, float]] = None`
- 逻辑：传入waypoints时直接使用；不传时回退到 `_find_safe_waypoints()` 动态算法

### 3. 修改所有 register_sailing 调用点（4处）

| 文件 | 位置 | 修改 |
|---|---|---|
| `scheduler/scheduler.py:646` | 船出航时 | 添加 `waypoints=get_waypoints(port_id, next_port_id)` |
| `scheduler/scheduler.py:1290` | 初始出航 | 添加 `waypoints=get_waypoints(home_port_code, next_port_id)` |
| `api/sim.py:245` | 场景出航 | 添加 `waypoints=get_waypoints(s.current_port, next_port_id)` |
| `services/state_serializer.py:176` | 状态恢复 | 添加 `waypoints=get_waypoints(ship.current_port or "", ship.next_port or "")` |

每处都需要 `from app.data.waypoints_loader import get_waypoints`。

### 4. 修复白色航迹线

**文件**: `frontend/components/CesiumGlobe.tsx`

- `getTrailColor()` 默认返回从白色改为船舶状态颜色+低透明度(alpha=0.15)
- 新增 `hexToRgb()` 辅助函数，将SHIP_COLORS的hex转为RGB
- 调用改为 `getTrailColor(ship.state, ship.cii_rating)`（原来是 `(ship.cii_rating, ship.co2_emissions)`）

### 5. 同步上海港坐标

| 文件 | 修改 |
|---|---|
| `backend/app/data/aeu_data.py` | CNSHA: (30.6306, 122.0733) → (30.5821, 121.0734) |
| `backend/app/data/port_coordinates.csv` | CNSHA: 121.4531,31.2187 → 121.0734,30.5821 |
| `frontend/data/port_coordinates.csv` | 已是正确值 30.5821, 121.0734 |
| `frontend/data/route_waypoints.csv` | china_tao_sha 新增seq3: (31.30, 121.70) 平滑过渡 |

### 6. 修复 Cesium 加载失败

**文件**: `frontend/app/layout.tsx`

- Cesium CSS/JS 从 `cesium.com` CDN 改为本地 `/cesium/` 路径
- 删除 `<Script>` 标签（CesiumGlobe.tsx 自己动态加载）

## 数据流对照（修复后）

```
route_waypoints.csv (26条航段)
  ├── 前端 csvLoader.ts → SEGMENT_MAP → buildRouteFromSequence() → 画彩色航线
  └── 后端 waypoints_loader.py → get_waypoints(from, to) → register_sailing(waypoints=...) → 船位置插值
  
两端使用同一份CSV → 船轨迹和航线100%一致
```

## 操作流程

修改航路点后的完整操作步骤：

1. 编辑 `frontend/data/route_waypoints.csv`
2. 复制到后端: `cp frontend/data/route_waypoints.csv backend/app/data/route_waypoints.csv`
3. 清缓存: `rm -rf frontend/.next`
4. 重启后端: 先reset仿真再start（否则旧状态不刷新航路点）
5. 重启前端: `npm run dev`

## 调试技巧

- **Ctrl+D**: 开启Cesium坐标调试模式，鼠标移动显示经纬度
- **后端验证**: `conda run -n shipping_sim python -c "from app.data.waypoints_loader import get_waypoints; print(get_waypoints('CNTAO','CNSHA'))"`
- **仿真重置**: 修改后端代码后必须 `curl -X POST /api/sim/reset` 再 `/api/sim/start`

## 注意事项

- CSV格式: `segment_id,from_port,to_port,seq,lat,lon,description`
- `from_port`/`to_port` 必须使用 UN/LOCODE 格式（如 `CNTAO`，不是内部ID如 `TAO06`）
- 反向航段由 `get_waypoints()` 自动翻转，无需在CSV中单独定义
- `lat`/`lon` 列顺序：lat在前(纬度)，lon在后(经度)
- 添加新航段后，需确认前端 `AEU_ROUTES` 的 `sequence` 中对应港口对有该航段
- `waypoints_loader.py` 在模块导入时一次性加载CSV，修改CSV后需重启后端
